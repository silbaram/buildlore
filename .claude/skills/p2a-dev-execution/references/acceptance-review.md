# Functional acceptance review

Read this reference only when `reviewPasses.acceptance` is `on`, when an independent acceptance pass was explicitly requested under `opt_in`, or when resuming an existing acceptance run. Do not use it for an envelope with a required visual contract.

After all iteration work is done and integrated, run `p2a execute accept --artifacts <artifact-root> --agent-tool <reviewer>`. This creates one `final_acceptance_review` run in the canonical workspace with `isolation.mode: none`, no changed files, and criteria derived from the current iteration's additions to Gate B `product.core_flows` and `product.success_criteria`.

The owner executes behavior commands with `p2a runs verify --run-id <id> --artifacts <root> --verify-command 'custom:<command>'`. Before invoking `p2a-acceptance-reviewer`, read the exact target run and preflight its complete `acceptanceReview.criteria` ref set against the recorded verification entries. Treat the sealed run contract as authoritative: new runs are scoped to the current iteration, while a legacy run may retain its cumulative contract. Do not replace either with the product spec or a summarized or hand-copied subset. Every criterion must have relevant candidate evidence that can be copied verbatim from an executed `source: command|config` entry with `status: passed`, integer `exitCode: 0`, and meaningful `stdoutTail`. If any criterion lacks such evidence, record the missing behavior evidence or block the run; do not invoke the reviewer.

After the preflight passes, invoke the reviewer with the exact run path rather than restating its contract in the prompt. The reviewer uses only read-only file inspection and search to load the approved spec, exact run, and recorded evidence; a provider may use read-only shell commands when that is how it exposes repository inspection. The reviewer never runs product behavior, tests, builds, lint, typechecking, lifecycle, network, or other implementation commands. Save its `p2a.acceptance_review.v1` sidecar as `<runId>.acceptance-review.json`. Before persisting, require the returned case count and criterion ref set to match the run contract exactly. Manual or unexecuted evidence is invalid, and exit zero with empty, irrelevant, or spawn-error output does not prove behavior.

Finish requires complete coverage and `confirm_behavior`, then seals the sidecar and canonical workspace hashes. Later workspace changes require a new review. A blocked review reopens its remediation owner.
