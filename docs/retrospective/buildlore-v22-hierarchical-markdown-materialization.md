# BuildLore v0.2.2 계층형 Markdown Wiki 생성 회고

## Observed issue

1. P2A 내부 Node.js 자식 프로세스가 관리형 샌드박스에서 `spawnSync .../node EPERM`으로 반복 중단됐다.
2. 동일한 작업공간 리비전에서 일시적으로 실패한 테스트가 재실행에서는 통과했지만, 이전 실패 기록 때문에 실행 종료가 거부됐다.
3. 구현 실행에서 전체 검증을 통과한 뒤에도 최종 증거 실행이 같은 전체 검증을 다시 수행했다.

## User impact

1. 제품 결함이 없는데도 권한 승인, 명령 재실행, 예약된 실행 복구가 반복됐다.
2. 작업이 일시적으로 차단 상태가 되었고, 새 실행에서 체크포인트와 전체 검증을 다시 수행해야 했다.
3. 종료 검증 시간이 늘었으며, 5초 경계에 걸린 대용량 제안 테스트가 전체 테스트 부하에 따라 다시 흔들릴 가능성이 확인됐다.

## Suggested improvement

1. P2A가 자식 프로세스 실행 가능성을 사전 점검하고, 샌드박스 거부를 제품 실패와 분리하며, 예약된 동일 실행을 한 번에 재개할 수 있는 명령을 제공한다.
2. 동일한 작업공간 리비전과 명령에서는 가장 최근의 성공 결과가 이전의 일시적 실패를 대체하도록 실행 종료 동작을 문서화된 계약과 일치시킨다. 대체가 불가능하다면 작업 및 체크포인트 상태를 보존한 깨끗한 증거 재시도 실행을 자동 생성한다.
3. 현재 리비전의 깨끗한 전체 검증 결과를 반복 개발의 최종 증거로 재사용하고, 회고처럼 문서만 변경된 뒤에는 관련 범위 검증만 요구한다.
4. 프로젝트의 184개 제안 파티셔닝 테스트에는 명시적인 테스트별 제한 시간 또는 성능 기준을 두어 전체 테스트 부하와 기능 실패를 구분한다.

## Evidence

- P2A의 실행 시작, 체크포인트, 종료 및 최종 검증 경로에서 `spawnSync .../node EPERM`이 반복됐고, 동일 명령을 허용된 환경에서 다시 실행하면 통과했다.
- 184개 제안 파티셔닝 테스트는 전체 테스트에서 약 5.18초가 걸려 5초 제한을 넘었지만, 단독 실행은 약 2.16초에 통과했고 같은 리비전의 전체 재실행도 통과했다.
- 실행 종료 시 `finished run cannot include failed verification: test:npm test` 오류가 발생해 깨끗한 재시도 실행이 필요했다.
- 재시도 실행에서는 네 개 체크포인트와 `npm test`, `npm run lint`, `npm run typecheck`가 모두 통과했고, 별도 최종 증거 실행에서도 같은 세 검증이 통과했다.
- 이 과정에서도 Markdown Wiki 생성 상태는 준비 완료였고, 의미 인덱스 사용 가능 상태와 의미 검색 성공 결과가 유지됐다.
