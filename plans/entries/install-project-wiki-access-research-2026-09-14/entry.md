# BuildLore 설치 및 프로젝트별 중앙 Wiki 접근 방향 조사

## 사용자 요청과 출처

현재 대화의 사용자 원문: “개선을 해야하는데 빌드로더의 설치 그리고 각 푸러젝크에서 빌드로더의 증앙식 지식 저장서에서 자신의 wiki를 읽는 방식 개선이야 다른 포르젝트들은 이문제를 어떻게 해결하는지 조사하고 최선에 방향성을 잡아”.

앞선 대화에서 설치가 소스 빌드 중심이고, CLI에는 Wiki 조회가 있지만 MCP 연결이 없으며, 허브 cwd와 명시적 project ID를 요구한다는 점을 검토했다. 사용자는 이번에 설치부터 다른 소스 프로젝트의 AI가 자기 Wiki를 읽는 과정까지 개선 방향을 조사하도록 요청했다.

## 이번 범위

공식 문서와 공개 저장소를 조사하고 현재 BuildLore 구현과 비교하여 설치, 프로젝트 바인딩, CLI/Skills/MCP 연결, Git 동기화 및 읽기 격리의 권장 방향과 검증 기준을 로컬 보고서에 기록한다. 외부 도구의 설치·실행 벤치마크, 제품 구현, 외부 게시, 기존 iteration 전환은 이번 조사에 포함하지 않는다. 기존 작업 트리 변경을 보존한다.

사용자는 중앙화 형태 질문의 1번인 ‘내 PC의 여러 프로젝트에서 공유’를 후속 입력 ‘1’로 선택했다. 한 PC의 복수 소스 체크아웃이 하나의 로컬 허브를 공유하는 구성을 기본 범위로 확정한다. 다른 PC와의 Git 동기화는 후속 확장 시나리오다. 이 선택은 조사 전제를 확정하며 제품 구현이나 기존 iteration 교체를 새로 지시하지 않는다.

## 산출물과 완료 기준

동일 디렉터리 REPORT.md에 비교 근거, 권장 사용자 흐름, 대안의 장단점, 단계별 우선순위 및 검증 기준을 기록한다. 문서상의 기능과 실제 실행 검증을 구분하며 제안 명령을 현재 구현된 명령으로 표시하지 않는다. provenance.json에 사용자 요청, entry/report 및 조사 출처를 결속한다.

로컬 entry를 p2a validate로 검증하고 p2a next --entry로 진입 경로를 확인한다. 조사와 무관한 기존 구현이나 lifecycle 전환은 수행하지 않는다.
